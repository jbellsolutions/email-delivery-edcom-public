# Deployment Template

This is a generalized checklist for building a self-hosted EmailDelivery.com CE stack without exposing live infrastructure details.

## 1. Choose Roles

Use separate roles for platform and sending when possible.

```text
S1 Platform
  - Web UI and admin API
  - HTTPS ports
  - No outbound bulk sending requirement

S2 Clean MTA
  - Dedicated sending IP
  - Outbound port 25 verified
  - Clean engaged traffic only

S3 Optional Gray MTA
  - Separate IP and domain
  - Re-engagement only after suppression
```

## 2. Verify The Sending IP

Before installing the MTA:

- Confirm outbound port 25 works from the server.
- Check major public blocklists.
- Confirm the provider allows mail transfer agent use.
- Set reverse DNS/PTR before sending.
- Confirm PTR forward-confirms back to the sending IP.

Do not build on an IP that is already listed or blocked.

## 3. Publish Authentication DNS

For each sending lane:

- A record for the sending hostname.
- SPF authorizing only the lane IP.
- DKIM generated by the ESP/MTA.
- DMARC record with reporting, then enforcement when stable.
- MX so bounces and feedback can return correctly.
- PTR/HELO alignment.

## 4. Configure Routes

Inside the ESP:

- Create a sending connection for the MTA.
- Create a delivery policy.
- Create a postal route from a customer/account to that policy.
- Publish changes after editing policies, routes, warmups, or servers.

No route means no send.

## 5. Warm Up

Start with engaged contacts only.

Recommended operating controls:

- Daily cap per IP.
- Slow ramp.
- Suppression before re-engagement.
- Complaint threshold below 0.1%.
- Bounce monitoring.
- Immediate pause on authentication failures.

## 6. Operate Safely

- Store secrets outside git.
- Rotate keys if they were ever pasted into chat or logs.
- Back up config, database, and DKIM material privately.
- Keep clean and gray lanes isolated.
- Do not publish live route IDs, API keys, customer IDs, or server identities.
